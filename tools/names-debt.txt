# names-debt.txt — grandfathered idiomatic `loc_` CELL consts (KNOWN SHRINKING DEBT).
#
# The rule (docs/runbook.md "A cell earns its DESCRIPTIVE identifier…" / reviewer-rules.md R31):
# `loc_<addr>` is the TRANSLATED layer's identifier and is NEVER a valid idiomatic CELL const
# name. A confidently-read cell owes a DESCRIPTIVE name (PLAYER_X / HIGH_SCORE style); an
# unknown-role cell is keep-hex (a bare literal, no const). So every top-level
# `export const loc_<hex> = 0x<hex>;` in a game's games/<game>/idiomatic/names.js is a violation,
# enforced mechanically by tools/names_consistency.py.
#
# This file grandfathers the loc_ cell consts that ALREADY existed when the gate landed, so the
# gate does not block current work. It is an allowlist of SPECIFIC (game, address) pairs — NOT a
# whole-game exemption — so a NEW loc_ cell (in frogger, timeplt, or any game) still FAILS
# immediately, and a new game starts with zero entries here (enforced from routine #1).
#
# Karl 2026-08-17 (his rule [[code-cells-get-descriptive-names]]: role-UNDERSTOOD -> DESCRIPTIVE name,
#   role-UNKNOWN -> `loc_<addr>`). So this allowlist holds two kinds of loc_ cell, both still a specific
#   reviewed (game, address) — NEVER a whole-game exemption:
#   (a) the SHRINKING descriptive-rename debt — cells whose role IS known; rename each (value-identical +
#       update importers) until gone;
#   (b) genuinely-ungrounded cells whose role is UNKNOWN, parked as loc_ per the rule; promote to a
#       descriptive name once MAME stage-B grounding fixes the role. Add a (b) line only for a cell that is
#       truly role-unknown after tracing — not to dodge naming a cell whose role you can read.
#
# Format: one `<game> 0x<addr>` per line. `#` comments and blank lines are ignored.

#
